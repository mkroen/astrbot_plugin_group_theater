# 群友四格小剧场

AstrBot 插件：取材后一次给出多个完整四格小剧场候选，以合并转发聊天记录展示，管理员选 ID 直接出图。版本 **0.2.0**。

参考 [通用图片生成插件](https://github.com/mkroen/astrbot_plugin_generic_image_gen) 的协议分类与头像处理思路，重新实现选材、分镜、持久化状态和额度控制。适用于 AstrBot ≥4.28.0、OneBot/NapCat 群聊。

## 工作方式

1. 管理员发 `/小剧场 取材 120`，按需读取最近聊天，不常驻收集消息。
2. 一次文字模型调用默认准备3个不同候选，每个聚焦一个短场景，提前生成 **铺垫 → 推进 → 转折 → 包袱** 完整分镜。素材不足或校验筛除后可以少于3个。
3. 插件返回一条合并转发聊天记录：首条说明选择方式，之后每个候选占一条，显示标题、ID、出演群友、四格动作和台词。长动作在预览中简写，完整内容已保存。
4. 直接发送 `/小剧场 出图 <ID>`，使用已保存的分镜绘图，不需要改稿，也不再次调用编剧。人物头像在这时获取，并按角色逐一传给绘图模型。
5. 同一草稿成功后重复出图命令只发送缓存图片。失败、超时或重启中断都不会自动补发。

取材编剧会消耗文字模型额度，多个候选共用一次请求；出图只生成选中的候选。插件不识别群聊里的图片，不创建自动出图任务，也不注册 LLM 绘图工具。聊天记录中的发送者统一标注“小剧场候选”，不会冒充群友真实发言。

## 安装与配置

通过 AstrBot 管理面板的插件 ZIP 安装入口上传发布包；也可把本目录的运行文件放入 `data/plugins/astrbot_plugin_group_theater/`，安装 `requirements.txt` 后重载插件。不要上传 `.venv`、测试缓存或开发环境。

可在 AstrBot 插件管理中通过仓库地址安装：

```text
https://github.com/mkroen/astrbot_plugin_group_theater
```

首次安装默认关闭，群白名单为空。配置后才启用：

| 配置 | 建议 |
| --- | --- |
| 启用小剧场 | 配置完成后打开 |
| 允许使用的QQ群号 | 填入要测试的群号 |
| 编剧文字模型 | 选择 AstrBot 中已有的文字模型 |
| 绘图协议 | 按服务商支持的入口选择，详见下表 |
| API基础地址 | 例如 `https://api.example.com/v1`，替换为实际服务地址 |
| 复用提供商凭据ID | 填提供商源ID，而非模型ID；也可使用独立密钥 |
| 独立API密钥 | 复用源时留空；有值时优先使用 |
| 绘图模型ID | 默认留空，填写入口实际支持的图片生成模型ID |
| 使用群友头像 | 默认开启 |
| 每次取材候选数 | 默认3，范围1至5 |
| 额度 | 默认整个插件每5小时最多提交1次，跨群共享 |

只有 **AstrBot 管理员** 能操作，不等于任意QQ群管理员。草稿仅允许创建人在原群访问。留空编剧模型会使用当前会话的文字模型。

本插件额度只统计自己的提交，不能读取或保护整个上游账号的额度。其他插件或客户端仍可能消耗同一账号。

## 协议选择

| 协议 | 请求入口 | 头像参考 |
| --- | --- | --- |
| `openai_chat` | `/v1/chat/completions` | 多模态 `image_url`；上游必须支持图片输出 |
| `gemini` | `/v1beta/models/{model}:generateContent` | `inlineData`，原生 `imageConfig` |
| `openai_images` | `/v1/images/generations` 或 `/v1/images/edits` | 有头像时使用 multipart edits |

API地址填写基础地址，不带最后的操作路径。Chat 下画幅和分辨率写入提示词；Gemini 原生用结构化参数。OpenAI Images 的尺寸、质量等由入口决定，质量和格式留空则不传。

OpenAI Images 兼容绘图入口选择 `openai_images`，模型ID、尺寸和多图 edits 支持以服务方为准。只支持 generations 的入口应开启“仅文生图”，并关闭头像；插件不会静默丢弃参考图。

默认不读取环境代理，留空代理即直连。下载返回图片不携带 API 密钥，不跟随重定向，仅接受公开 HTTPS 地址；私网图片链接不支持。

## 命令

| 命令 | 用途 |
| --- | --- |
| `/小剧场` | 帮助 |
| `/小剧场 取材 120` | 读取最多200条/12000字，默认返回3个已完成分镜的候选 |
| `/小剧场 编剧 昵称：发言` | 粘贴素材，换行继续输入；不会猜测QQ号或绑定头像 |
| `/小剧场 分镜 ID` | 查看草稿 |
| `/小剧场 出图 ID` | 明确确认生成，或重发已有缓存 |
| `/小剧场 状态 ID` | 查看状态 |
| `/小剧场 取消 ID` | 取消尚未出图的草稿，不能撤回已提交的上游请求 |
| `/小剧场 额度` | 查看插件额度占用 |
| `/小剧场 清理` | 删除过期素材与成图 |

`get_group_msg_history` 是协议端扩展能力；实际返回条数由 NapCat 等协议端决定。如果取不到历史，请使用粘贴编剧。第一版不跨页追溯旧聊天。

## 状态与数据

草稿和额度保存在 AstrBot 插件数据目录的 `theater.db`，结果在 `images/`。默认保留24小时：到期即拒绝访问，下次操作或手动清理时删除，不运行后台清理任务。删除不是磁盘取证意义的安全擦除，服务器备份也可能保留历史副本。

取材文字、昵称会发送给所选编剧服务；本插件不把元数据中的QQ号加入编剧提示，但聊天正文可能本身含个人信息。出图会发送已确认的分镜和选中人物头像。头像只在内存处理，不单独落盘，不分析群消息图片。

状态：`draft` → `rendering` → `done` / `failed` / `unknown`；草稿也可 `cancelled`。失败或结果未知时该草稿锁定，不允许直接重发。需等待额度恢复、重新创建草稿，再人工确认。额度预占发生在提交之前，极小的崩溃窗口可能保守地计数但没有发出请求。

目前仅支持单个插件实例管理同一数据库，不用于多个 AstrBot 实例共享数据库。人物一致性、中文气泡准确度和笑点效果依赖模型，程序校验无法保证审美质量。

## 开发验证

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

测试使用模拟文字模型、MockTransport 和本地小图片，不消耗绘图额度。AstrBot 命令接口已对照现有4.28.2环境源码核对；尚未在实际群中完成新插件端到端验收。

人工验收先只检查帮助、白名单、取材和合并转发显示；确认候选人物及剧情后，再由管理员自行执行一次出图。重复同一出图命令应仅重发缓存。合并转发需要协议端支持，尚未进行真实群消息发送测试。
